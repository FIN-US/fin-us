# Fin-Us 사용 설명서

이 문서는 **Fin-Us를 실제로 어떻게 쓰는가**를 다룹니다. 아키텍처 설명은 [README](../README.md)에 있습니다.

---

## 1. 이 서비스가 대신해 주는 일

Fin-Us는 한 문장으로 **"관심 있는 종목을 대신 지켜보다가, 의미 있는 변화가 생기면 텔레그램으로 알려주고, 그 자리에서 매매까지 할 수 있게 해 주는 시스템"** 입니다.

구체적으로 세 가지를 합니다.

1. **감시** — 10분마다 보유 종목과 관심 종목의 뉴스·공시를 확인합니다. 이전과 달라진 게 없으면 아무것도 하지 않고, 새로운 신호가 있을 때만 AI 분석을 돌립니다.
2. **분석** — 역할이 다른 6개의 AI 에이전트(뉴스 분석가, 자산 운용 관리자, 전략 수립가 등)가 각자 담당 도구로 데이터를 가져와 판단합니다. 한 모델이 전부 처리하지 않는 이유는 환각을 줄이기 위해서입니다.
3. **집행** — 분석 결과를 텔레그램으로 보내고, 사용자가 확인 버튼을 누르면 한국투자증권 API로 실제 주문을 냅니다.

### 세 가지 사용 경로

| 경로 | 용도 | 접속 |
| :--- | :--- | :--- |
| **텔레그램 봇** | 주 사용 경로. 알림 수신, 조회, 매매 전부 가능 | 본인 봇과 1:1 대화 |
| **웹 대시보드** | 분석 리포트와 기록을 눈으로 확인 | http://localhost:5173 |
| **REST API** | 직접 호출하거나 다른 시스템과 연동 | http://localhost:8000/docs |

일상적으로는 **텔레그램만 쓰면 됩니다.** 나머지 둘은 확인·개발용입니다.

## 2. 처음 시작하기

### 2-1. 준비물

API 키 5종이 필요합니다. 전부 있어야 하는 건 아니고, **쓰려는 기능에 해당하는 것만** 발급받으면 됩니다.

| 키 | 무엇에 쓰이나 | 없으면 |
| :--- | :--- | :--- |
| `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY` | AI 분석 전반 | 분석 기능 전체 불가 |
| `KIS_API_KEY` / `KIS_API_SECRET` / `KIS_ACCOUNT_NO` | 잔고·현재가·수급 조회, 매매 | 계좌 관련 기능 전부 불가 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 뉴스 수집 | 뉴스 기반 감시 불가 |
| `DART_API_KEY` | 공시·실적 조회 | 공시 signal, `/earnings` 불가 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 텔레그램 알림·명령 | 텔레그램 경로 전체 불가 |

**텔레그램 봇 토큰 발급 방법** (README에 안내가 없어 여기 적습니다)

1. 텔레그램에서 [@BotFather](https://t.me/BotFather)를 찾아 `/newbot` 을 보냅니다.
2. 봇 이름과 사용자명(`_bot`으로 끝나야 함)을 정하면 토큰을 줍니다 → `TELEGRAM_BOT_TOKEN`
3. 방금 만든 봇에게 아무 메시지나 한 번 보냅니다.
4. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 를 엽니다.
5. 응답의 `"chat":{"id":...}` 값이 `TELEGRAM_CHAT_ID` 입니다.

> 이 봇은 `TELEGRAM_CHAT_ID` 와 일치하는 대화에서만 명령을 받습니다. 다른 사람이 봇을 찾아 명령해도 무시됩니다.

### 2-2. 설정

대화형 CLI가 물어보는 대로 답하면 `.env`가 만들어집니다.

```bash
bash scripts/setup_env.sh
```

기능 묶음별로 "쓸 건가요?"를 먼저 묻고, 쓴다고 한 것만 값을 입력받습니다.

- 뉴스/공시 데이터 (Naver, OpenDART)
- 계좌 조회와 매매 (KIS)
- Telegram 알림과 시각화
- 로컬 Ollama 모델

직접 편집하고 싶으면 `.env.example`을 복사해서 고쳐도 됩니다.

설정이 제대로 됐는지는 이걸로 확인합니다.

```bash
bash scripts/check_env.sh
```

### 2-3. 실행

**Docker로 한 번에 (권장)**

```bash
bash scripts/setup_deps.sh   # MCP 의존성 설치 + 이미지 빌드
bash scripts/run_stack.sh    # 전체 스택 기동
```

뜨는 서비스와 포트는 다음과 같습니다.

| 서비스 | 포트 | 역할 |
| :--- | :--- | :--- |
| `frontend` | 5173 | 웹 대시보드 |
| `backend` | 8000 | API·스케줄러·텔레그램 봇 |
| `finus-nat` | 8001 | 멀티 에이전트 엔진 |
| `redis` | 6379 | 신호 중복 방지 캐시 |

`backend`는 `finus-nat`과 `redis`가 정상(healthy)이 된 뒤에 뜹니다. `finus-nat`은 기동에 최대 90초까지 걸릴 수 있습니다.

**전부 지우고 처음부터 다시 하려면**

```bash
bash scripts/reset_clean.sh
```

컨테이너·볼륨·로컬 이미지와 `node_modules`/`venv`/`__pycache__`를 지웁니다. 되돌릴 수 없으니 확인 후 실행하세요.

## 3. 텔레그램으로 쓰기

가장 많이 쓰게 될 경로입니다. 봇과의 1:1 대화창에서 `/help`를 보내면 명령 목록과 버튼이 나옵니다.

### 3-1. 조회

| 명령 | 하는 일 |
| :--- | :--- |
| `/balance` | 예수금·총자산·보유 종목과 수익률 |
| `/quote 삼성전자` | 현재가 |
| `/trend 삼성전자` | 외국인·기관·개인 수급 |
| `/earnings 삼성전자 2025Q1` | DART 실적 + 뉴스 기반 구조화 리포트 |
| `/catalysts 삼성전자` | 예정된 실적·배당·공시·주주총회 일정 |
| `/visualize` | Unity 포트폴리오 시각화 링크 |

`/earnings`는 첫 줄에 `🟢 호재` / `🔴 악재` / `⚪ 중립` 판정을 표시합니다. OpenDART가 주지 않는 컨센서스 데이터는 **추정하지 않고 "데이터 없음"으로** 표시합니다.

### 3-2. 관심 종목 — 감시 대상을 정하는 곳

```
/watch add 카카오
/watch remove 카카오
/watch list
```

**여기 등록한 종목이 10분마다 자동 감시됩니다.** 보유 중인 종목은 등록하지 않아도 자동으로 감시 대상에 포함됩니다.

> 계좌 조회에 실패하면 감시 대상이 기본값(`삼성전자`, `SK하이닉스`, `현대차`, `NAVER`)으로 대체됩니다. 갑자기 엉뚱한 종목 알림이 온다면 KIS 연결을 의심해 보세요.

### 3-3. 매매 — 안전장치 이해하기

주문은 **반드시 두 단계**입니다. 명령 하나로 바로 체결되지 않습니다.

```
/buy 삼성전자 10           ← 시장가 매수 (지정가 생략)
/buy 삼성전자 10 70000     ← 지정가 매수
/sell NAVER 2 200000      ← 지정가 매도
```

입력하면 **확인 메시지**가 뜹니다. 종목명, 종목코드, 수량, 주문 유형, 현재가, 주문가능금액이 표시되고 `✅ 확정` / `❌ 취소` 버튼이 붙습니다.

- 확정하려면 버튼을 누르거나 `/confirm`
- 취소하려면 버튼을 누르거나 `/cancel`
- **60초가 지나면 자동으로 만료**됩니다
- 대기 중인 주문이 있으면 새 주문을 낼 수 없습니다. 먼저 처리해야 합니다

자연어로도 됩니다. 확인 단계는 동일하게 거칩니다.

```
삼성전자 1주 시장가로 매수해줘
NAVER 2주 200,000원에 매도해줘
```

**실계좌 주문의 3중 게이트**

실제 돈이 나가려면 아래가 **전부** 충족돼야 합니다. 하나라도 빠지면 차단됩니다.

1. `.env`에 `KIS_ORDER_ENV=real`
2. `.env`에 `KIS_REAL_ORDER_ENABLED=true`
3. 60초 안에 사용자가 직접 확정

기본값은 모의투자(`demo`)입니다. 실계좌로 바꾸기 전에 모의투자에서 충분히 확인하세요.

> **주문 불가 종목이 있습니다.** 종목코드가 `0001A0` 같은 영숫자이거나 9자리인 종목(코스닥 스팩·리츠·ETN·펀드, 전체의 약 18%)은 현재 주문을 지원하지 않습니다. 조회는 정상이지만 주문 시 "이 종목은 현재 주문을 지원하지 않습니다"가 뜹니다.

### 3-4. 알림 모드

```
/alerts urgent   ← 기본값. 긴급 분석만
/alerts all      ← 모든 분석 결과
/alerts off      ← 분석 알림 끄기
/alerts status   ← 현재 설정 확인
```

`urgent`는 분석 결과에 긴급 표시가 붙은 것만 보냅니다. 조용히 쓰고 싶으면 기본값 그대로 두면 됩니다.

**모닝 브리핑은 이 설정과 무관하게 전송됩니다.** 정기 브리핑이라 긴급 알림 게이트와 분리돼 있습니다.

### 3-5. 그 외 아무 말이나

슬래시 명령이 아닌 일반 문장은 AI 에이전트에게 그대로 전달됩니다.

```
내 포트폴리오에서 리스크가 큰 종목은?
반도체 섹터 최근 분위기 어때?
```

텔레그램 대화는 `telegram:{chat_id}` 라는 별도 대화 ID를 쓰므로, 스케줄러가 만드는 분석 리포트와 대화 이력이 섞이지 않습니다.

## 4. 가만히 둬도 자동으로 일어나는 일

백엔드가 떠 있으면 아래가 자동 실행됩니다.

| 언제 | 무엇을 |
| :--- | :--- |
| **10분마다** | 감시 종목의 뉴스·공시 확인 → 새 신호가 있을 때만 AI 분석 → 조건 충족 시 텔레그램 알림 |
| **매일 08:30** | 촉매 이벤트 캘린더 갱신. D-1/D-0 이벤트 사전 알림 |
| **평일 08:30** | 모닝 브리핑 전송 |
| 60초마다 | 헬스 체크(ping) |

**신호 중복 방지**: 같은 뉴스로 반복 분석하지 않도록 Redis에 이전 신호의 해시를 저장합니다(14일 보관). 내용이 바뀌지 않으면 AI 호출 자체를 건너뜁니다. API 비용이 절약되는 지점입니다.

**모닝 브리핑 구성**
- 오늘의 시장 요약 (전일 미국·선물 동향)
- 관심종목 동향 (종목별 최신 뉴스와 수급)
- 오늘의 트레이딩 아이디어
- 주요 촉매 이벤트

알림이 오는지 미리 확인하려면:

```bash
# 실제 전송
docker compose exec backend uv run --project /app/backend python /app/backend/scripts/send_test_telegram_alert.py

# 형식만 확인 (전송 안 함)
docker compose exec backend uv run --project /app/backend python /app/backend/scripts/send_test_telegram_alert.py --dry-run
```

## 5. 웹 대시보드

http://localhost:5173

종목을 검색하면 AI 분석 리포트를 볼 수 있고, 저장된 매매 기록과 리포트 목록을 확인할 수 있습니다. WebSocket으로 실시간 알림도 받습니다.

> **알아두세요**: 화면의 포트폴리오 영역은 현재 항상 비어 있습니다. 계좌 데이터를 DB에 동기화하는 기능이 아직 구현되지 않았습니다([이슈 #122](https://github.com/FIN-US/fin-us/issues/122)). 실제 잔고는 텔레그램 `/balance` 로 확인하세요.

## 6. REST API

http://localhost:8000/docs 에서 대화형 문서(Swagger)를 볼 수 있습니다.

| 엔드포인트 | 설명 |
| :--- | :--- |
| `GET /api/v1/analyze?stock=SK하이닉스&provider=nat` | AI 종합 분석 |
| `GET /api/v1/news?stock=삼성전자` | 뉴스 |
| `GET /api/v1/disclosures?stock=삼성전자` | DART 지분공시 signal |
| `GET /api/v1/trading/trend?stock=삼성전자` | 수급 |
| `GET /api/v1/trading/balance` | 계좌 잔고 |
| `GET /api/v1/db/reports` | 저장된 분석 리포트 |
| `GET /api/v1/db/trades` | 매매 이력 |
| `GET /api/v1/db/diary` · `POST` | 투자 일지 조회·작성 |
| `WS /api/v1/ws` | 실시간 알림 |
| `GET /health` | 헬스 체크 |

> **주의**: 현재 API에 인증이 없습니다. 외부에 포트를 열지 마세요.

## 7. 자주 겪는 문제

**종목명을 못 알아들어요**
`mcp-trading/data/stocks.json` 캐시에 없는 종목입니다. 6자리 종목코드를 직접 입력하거나 캐시를 갱신하세요.
```bash
python3 mcp-trading/scripts/update_stock_master.py
```

**"주문 준비 실패: 종목코드를 확인할 수 없습니다"**
`resolve_stock_code`가 종목을 찾지 못한 경우입니다. 종목명 철자를 확인하거나 종목코드로 입력해 보세요.

**"실계좌 주문은 KIS_REAL_ORDER_ENABLED=true 설정이 필요합니다"**
의도한 것이면 `.env`에 해당 값을 넣고 스택을 재기동하세요. 의도하지 않았다면 실계좌 모드로 잘못 설정된 것입니다.

**텔레그램 봇이 반응이 없어요**
`TELEGRAM_CHAT_ID`가 본인 대화 ID와 일치하는지 확인하세요. 불일치하면 봇이 조용히 무시합니다.

**분석 알림이 안 와요**
`/alerts status`로 모드를 확인하세요. `off`이거나, `urgent`인데 긴급 조건에 걸리지 않았을 수 있습니다. `/alerts all`로 잠시 바꿔 확인해 보세요.

**컨테이너가 안 떠요**
`finus-nat`이 기동에 최대 90초 걸립니다. `docker compose logs -f finus-nat` 으로 확인하세요. `backend`는 `finus-nat`이 healthy가 돼야 시작합니다.

## 8. 알아둘 한계

정직하게 적어 둡니다. 전부 추적 중인 이슈입니다.

- **영숫자·9자리 종목코드는 주문 불가** — 전체 종목의 약 18%. 조회는 됩니다 ([#138](https://github.com/FIN-US/fin-us/issues/138))
- **웹 대시보드 포트폴리오가 항상 비어 있음** — 계좌→DB 동기화 미구현 ([#122](https://github.com/FIN-US/fin-us/issues/122))
- **API에 인증이 없음** — 외부 노출 금지
- **대기 주문이 메모리에만 있음** — 백엔드를 재시작하면 확인 대기 중이던 주문이 사라집니다 ([#63](https://github.com/FIN-US/fin-us/issues/63))
- **증권사에 제출된 주문은 `/cancel`로 취소되지 않습니다** — 취소는 확정 전 단계에서만 가능합니다

## 9. 용어

| 용어 | 뜻 |
| :--- | :--- |
| **MCP** | Model Context Protocol. AI가 외부 도구(뉴스·증권사 API 등)를 쓰게 해 주는 규약 |
| **NAT** | NVIDIA Agent Toolkit. 여러 에이전트의 협업을 제어하는 엔진 |
| **signal** | 감시 중 포착한 변화(새 뉴스, 새 공시). 신호가 있어야 AI 분석이 돌아감 |
| **촉매(catalyst)** | 주가에 영향을 줄 예정된 이벤트. 실적발표, 배당락, 주주총회 등 |
